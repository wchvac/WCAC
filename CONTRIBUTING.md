# Contributing to WCAC-OS

## Rules for Changes

1. Keep instructions simple and step-by-step.
2. Use plain language.
3. Avoid long paragraphs.
4. Add checklists whenever possible.
5. Do not remove working procedures without documenting why.
6. Test new forms or procedures in the field before calling them final.
7. Record major changes in `CHANGELOG.md`.

## File Naming

Use lowercase words separated by hyphens.

Example:

`replacement-job-closeout.md`

## Recommended Change Process

1. Identify the problem.
2. Write the proposed improvement.
3. Test it.
4. Revise it.
5. Approve it.
6. Update the related file.
